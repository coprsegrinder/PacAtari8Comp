# 25 - The Variable Catalogue (stage 41)

GENERATED by `python -I tools/analyze_variables.py --write docs/25-variable-catalogue.md`; the names, sizes and roles are written in `tools/zp_catalogue.py` (the **evidence** column: a chapter number = verified live there, `code` = read from `src/asm/pacman.s` for this catalogue and not tested separately, `OS` = a standard Atari OS variable); who reads and writes each variable is derived from the code. Tests: `tests/test_variables.py`.

**All the names of this table are applied** (checklist stage 3): `tools/labels.py` derives the symbols of the generated source `src/asm/pacman.s` from `tools/zp_catalogue.py`, a byte that is not the first of its variable is written `Name+k`, and the source rebuilds byte for byte (section 5). The names marked with a trailing `*` in the **Name** column were already given explicitly in `tools/labels.py` before that (the others were `zp_XX`). A variable touched by **one routine only** is LOCAL (a scratch of that routine; stage 42), by two or more GLOBAL.

## 1. Summary

- **Zero page:** 132 of the 256 bytes are used by the code, in **109 variables** (scalars, arrays, pointers): 81 GLOBAL, 28 LOCAL. 49 of the used bytes had an explicit name in `tools/labels.py` before stage 3 (marked `*`); the other 83 were `zp_XX` and now have the names of this table (section 5).
- **Arrays** (indexed by X): per ghost (4), per entity (ghosts and Pac-Man, 5) or per player (2). The per-entity arrays are 'structure of arrays': `EntityX,x`, `GhostState,x`, ... (stage 48).
- **Other RAM:** the OS shadows, the picture buffer, the tables built at start-up, the mazes, the screens and the player-missile memory (section 3).
- The routines are named as in `23-function-table.md`; the subsystem codes (BOOT, FRAME, ...) are those of `24-function-relationships.md`.

## 5. The names in the source (checklist stage 3)

`src/asm/pacman.s` is generated by `tools/make_asm.py` from the ROM and `tools/labels.py`; `labels.zp_name` returns, for a zero-page operand, the OS name, a name given in `GAME_ZP`, or the name of this catalogue (`Name` for the first byte of a variable, `Name+k` for the k-th). **83 zero-page bytes that were `zp_XX` now have these names**; no `zp_XX` is left in the source, and `tools/build_rom.py` rebuilds the ROM **byte for byte** (`tests/test_zp_names.py`).
