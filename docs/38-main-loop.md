## 1. The result

- **The program is two programs.** The **main program** is the key loop `$A4BA-$A559` of `Start`: it never returns and does no game logic; it reads the keys and the console and refreshes four colour bytes. **Everything else runs in interrupts**: the deferred vertical-blank handler `$A5FD` once per frame (all game logic, one call of `FrameDispatch`), and two display-list interrupt handlers (colour bands). The main program changes the game only through five keys: START / trigger (new game, `$A537`), SELECT, OPTION, the space bar (pause) and the end of the game-over countdown.
- **Every frame has one of 15 classes**, fixed by the dispatcher's tests in the order of the code (section 4); all 219987 frames of the 7 sessions fall in them, and only 25 different class-to-class transitions occur (section 5).
- **The handler never runs late**: in 219987 consecutive frames no handler entry was missed and the handler was never still running when the next one came (`$A5FD` to `JMP XITVBV`). A play frame takes a median of 37 scan lines (max 103) of the 262 of a frame; the heaviest frames are level end (234 lines), turn control (225 lines), play (103 lines); the smallest margin is **28 scan lines** (11% of a frame).
- **The frame by frame story** of a game is a short sequence of classes with fixed lengths (section 6): copyright 247 frames, title menu until START, the start tune 260 frames, then play; a death is 354 frames, the READY! wait 65, an eaten ghost's pause 33, the level end 187, the game-over countdown up to 1,800 (30 s).

$A4F5  CH = $FF;  if STRIG0 == 0 or STRIG1 == 0 goto $A537                           trigger starts a game ($A4FA-$A502)
$A504  c = CONSOL;  if c == 7 goto $A4BA                                             no console key

The vertical-blank handler (`$A5FD`): `$18` := 0 (the band counter of the display-list interrupts), `$45` -= 1, `FrameDispatch`, `ClipEntitiesOnTunnelRow` unless `EatPause` (`$E5`) is set, `JMP XITVBV`.
