## 4. In what order things run

### 4.1 Start-up (the code of `Start` in address order)

```
$A43E  jsr ExpandData
$A460  jsr SETVBV
$A481  jsr ClearPokeyRegisters
$A484  jsr Copy0800To0C00
$A487  jsr Copy0C00To1000
$A48A  jsr Copy0C00To1400
$A49B  jsr SetDisplayList
$A4A3  jsr InitBoard
$A4A6  jsr NewGameInit
$A4AD  jsr TitleClearScores2P
$A4B3  jsr TitleClearScores1P
```

Before these: the two `ExpandData` calls at `$A42B` / `$A43E` unpack the maze and charset (with `ReadSrcByte` / `ReadSrcHighNibble` / `WriteDstByte` / `AdvanceSrcPtr`), `SETVBV` installs the VBI at `$A460`. `$A477` is the **new-game entry** (`$A537` jumps here): clear the audio, restore and save both mazes, install the maze display list, `InitBoard`, `Sub_ADF1`, the title score clearing; then the key loop `$A4BA` runs for ever, and the whole game happens in the interrupt-time routines below (`docs/21`).

### 4.2 At interrupt time

1. **Display-list interrupts** (`DliHandler1`: the maze bands, `DliHandler2`: the title) change colours and `CHBASE` at scanlines (docs/15).
2. **Vertical blank** (`VbiHandler`, deferred): `FrameDispatch` (`Sub_A6CC`), then `Sub_AB48` (the tunnel clip) unless the pause flag `EatPause` is set.
3. `FrameDispatch` by the state `GameState`: 0 = the game frame (4.3), 1 = the copyright screen, 2 = wait, 3 = the title, 4 = the title after a game (docs/21).

So a ghost always sees Pac-Man's new position, and a contact found in a frame concerns the positions drawn at the end of the frame before.

### 4.4 The sequences that cross frames

- **New game**: `$A537` -> `$A477` (clear, copy mazes, `InitBoard`, `NewGameInit`) -> READY! with the start tune (`IntroRequest` = 2 steps, `DrawReadyScreen` at step $28) -> `$A800` first move (docs/21).
- **Ghost eaten**: contact -> `GhostEaten` ($A886: state $42, score, `EatPause` pause) -> `GhostEatenPause` ($B049, a block reached by a jump from the dispatcher) counts the pause down 32-33 frames -> colours restored; the eyes then walk home in `EyesAndHousePerFrame` (docs/18).
- **Death**: contact -> `$A923` -> `DeathSequence` (97 frames of freeze, ghosts hidden) -> `DeathAnimation` (16 frames) -> `TurnControl` (switch players or game over) -> the READY! wait (docs/20, 19).
- **Level complete**: `LevelComplete` (the last dot) -> `$AC18`: `ClearPokeyRegisters`, `DrawAllInPlace` (the entities drawn in place), ..., `InitBoard` (`$AC6F`), then `AdvanceLevel` (`$AC75`: `NewBoardInit`, `DrawLevelIndicator`, `DrawReadyScreen`) (docs/14, 20).
