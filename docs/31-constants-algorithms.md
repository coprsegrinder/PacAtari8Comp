## 4. The algorithms

Status: **LIVE** = checked against the running game (the chapter and the register `OPEN-VERIFICATION.md` name the sessions); **MODEL** = also executed here: the ROM routine run in `tools/cpu6502.py` against a model, section 5.

### A01 - Start-up and data expansion

- **Routines**: `Start`, `Init`, `ExpandData`, `ReadSrcByte`, `AdvanceSrcPtr`, `WriteDstByte`, `ReadSrcHighNibble`
- **Rule**: Clear zero page $18-$3F and $80-$FF; expand the type A stream (inline RLE: literal, repeat (c&$3F)+1, three bytes out) to the maze at $0800, the nibble tables to $0600 (high nibble then low nibble of each of 256 bytes), the type B streams (table-driven: `PixelPatternTable[c&$3F]` repeated (c>>6)+1 times) to the charset $3000 and the title charset $1808; start the key loop.
- **Tables and constants**: streams in ROM `$A003`, `$A1E1`, `$BE13`, `$BE95`; `PixelPatternTable`
- **Evidence**: 12; `tools/decode_streams.py`, `tests/test_streams.py`, `tests/test_nibble_map.py`
- **Status**: LIVE + MODEL (the ROM code run to `$A477` produces the same RAM images)

### A02 - Key loop, game start and game over

- **Routines**: `Start`, `CompareHighScore`, `TitleClearScores1P`, `TitleClearScores2P`, `DrawLabel1UP`, `DrawLabel2UP`, `BlinkPlayerLabel`
- **Rule**: Poll CONSOL and the keyboard with a debounce counter; START begins a game, SELECT toggles one / two players, OPTION steps `StartLevel` through 0,1,2,4,6,8,10,12; the space bar pauses; at game over a 30 s countdown (`$E2` steps of 8 jiffies) returns to the title; the high score is replaced when the player's score is larger.
- **Tables and constants**: `StartLevel` steps, `CountdownTimer` $E2
- **Evidence**: 21, 19; `tests/test_start_gameover.py`, `tests/test_pregame.py`
- **Status**: LIVE + MODEL (the key loop with START / SELECT / OPTION / space bar, the debounce and the restart: 5,000 passes; the title screens: 3,000 frames; `tools/algorithm_models6.py`, `tools/algorithm_models7.py`); the pause key is also modelled (`25`)

### A03 - The frame: dispatch and pacing by the jiffy clock

- **Routines**: `FrameDispatch`, `VbiHandler`, `ToggleLegPhase`
- **Rule**: The deferred VBI handler runs the whole game in one call: title states 1-4, and in state 0 the game frame in the order of the code (`24-function-relationships.md`, section 'one frame of play'). Everything slower than a frame is paced by `RTCLOK2` bits: every 4th jiffy the house, every 8th the chase and patrol timers, every 16th the ghost feet and the label blink.
- **Tables and constants**: `RTCLOK2` masks $03, $07, $0F
- **Evidence**: 24 (one frame in the order of the code), 17, 18, 20; `tests/test_timer_budgets.py`
- **Status**: LIVE + MODEL (`FrameDispatch` and `VbiHandler` run frame by frame against a model of the whole frame: the clocks, the intro, the death, the pause, the contacts, the pacing of every ghost; 30,000 frames, whole memory compared, `tools/algorithm_models7.py`)

### A04 - Display-list interrupts and colour bands

- **Routines**: `DliHandler1`, `DliHandler2`, `InitDisplay2`, `SetDisplayList`
- **Rule**: At each display-list interrupt the handler writes the colours of the next band (from `DliColors`, faded in attract mode by `DRKMSK` / `COLRSH`) and its `CHBASE` (`DliChbaseTable` on the title screen); `BandCounter` counts the bands and is cleared by the VBI.
- **Tables and constants**: `ColorsDli`, `DliChbaseTable`, `ColorsTitle`
- **Evidence**: 15, 06
- **Status**: LIVE (colours: 482,764 pixels checked, C-50) + MODEL (`DliHandler1`, `DliHandler2`, `SetDisplayList`, `InitDisplay2` against the code run with an interrupt frame, `tools/algorithm_models6.py`)

### A05 - Pac-Man's step

- **Routines**: `MovePacMan`
- **Rule**: Read STICK0; keep the wanted direction until it can be taken; cornering (a perpendicular turn forces a step); one step is 1 pixel sideways or 2 vertically; the sub-cell counters (0-3) and MazePtr (+-1 per 4 pixels, +-$28 per row) follow; the tunnel wraps x between $2A and $CA; frozen (bit 7 of `PacFrozen`) returns at once.
- **Tables and constants**: `MAZE_ROW_STRIDE`, `TUNNEL_X_*`, `NoReverseMask`
- **Evidence**: 20, 16; `tests/test_tunnel_clip.py`
- **Status**: LIVE + MODEL (`MovePacMan` 15,000 calls: joystick, cornering, sub-cells, MazePtr, tunnel wrap, chomp picture, `tools/algorithm_models4.py`)

### A06 - Dots, power pellets and the dot count

- **Routines**: `EatDotAtPacMan`, `PowerPelletCheck`, `PowerPelletEaten`, `BlinkPowerPellets`, `ShowPowerPellets`
- **Rule**: At each new cell test the maze byte through `MazePtr`: 1 = a dot (cleared, +10 points, the dot sound, `DotDelay` = 1, counted per player); 2 = the cell is cleared and nothing else happens here; the four power-pellet squares are recognised by position (`PowerPelletCheck`, with `PelletFlags`) and call `PowerPelletEaten` (50 points, the frightened period); the board is complete at 260 dots and pellets ($0104); the four pellet cells blink with the jiffy clock and follow `PelletFlags`.
- **Tables and constants**: `SCORE`: digits 1 / 5 in `ScoreAdd`
- **Evidence**: 20, 12
- **Status**: LIVE + MODEL (eating a dot 12,000 calls, a power pellet 15,000 calls, `tools/algorithm_models2.py`)

### A07 - Score: BCD addition, leading zeros, extra life

- **Routines**: `AddToScore`
- **Rule**: Add the six BCD digits of `ScoreAdd` (100,000 first) to the six screen cells of the player on turn, from the units upwards with decimal carry; a cell holds `$10 + digit`; a zero digit is blank unless a digit to its left is non-blank or a carry is pending, and the top digit zero is always blank; the amount is cleared; when the cell of the 10,000s becomes non-blank for the first time (`ExtraLifeFlag` = 0) the player gets one more life (+1 flag, +1 `Lives`).
- **Tables and constants**: `SCORE_DIGIT_MASK`, `SCORE_DIGIT_BASE`, cells `$202A-$202F` / `$2047-$204C`
- **Evidence**: 12, 19, C-23; `tools/algorithm_models.py`
- **Status**: LIVE + MODEL (6,000 additions)

### A08 - Speed pacing

- **Routines**: `MoveDelayTick`, `InitBoard`
- **Rule**: Each entity has `MoveDelayCount` (frames to the next step) and `MoveDelayCycle` (0-3). Every frame the count falls; at 0 the cycle advances (3 wraps to 0) and the count is reloaded from `MoveDelay[base[min(Level,6)] + cycle]` (Pac-Man: `PacMoveDelayBase`, ghosts: `GhostMoveDelayBase`); the routine returns A = 0 when the entity acts in this frame, $FF when it waits. A frightened ghost and a ghost in the tunnel row act only on every second run-out (`HalfSpeedToggle`).
- **Tables and constants**: `MoveDelay` $07AE (24), `PacMoveDelayBase`, `GhostMoveDelayBase`, `LEVEL_CLAMP_SPEED`
- **Evidence**: 14, 18; `tests/test_levels.py`
- **Status**: LIVE + MODEL (every level 0-255, 10,241 calls)

### A09 - Junction lookup

- **Routines**: `JunctionLookup`
- **Rule**: If the entity's y is one of the 10 lattice rows and x one of the 10 lattice columns it is at a lattice point: mask = `JunctionExits[row][col]`, carry set; on a lattice row between columns the mask is $0C (left / right), anywhere else $03 (up / down). A ghost's mask loses the reverse of its direction (`NoReverseMask[dir]`); on the squares beside the door (y $64, x $76 / $82) a frightened ghost gets up only, a normal ghost loses up (mask AND $0E, or up if nothing is left).
- **Tables and constants**: `JunctionYList`, `JunctionXList`, `JunctionExits`, `NoReverseMask`, `DOOR_*`
- **Evidence**: 13, 15, 18
- **Status**: LIVE + MODEL (29,184 calls)

### A10 - Steering at a lattice point

- **Routines**: `SteerToTarget`
- **Rule**: Wanted vertical direction: none if y equals the target's, else toward the target (away from it when the ghost is frightened); wanted horizontal the same on x. ### A11 - Ghost state machine

- **Routines**: `GhostBehaviour`, `ForceChase`, `ChaseTimerSirenSight`, `GhostStartRoute`, `GhostSelectPatrol`, `GhostPatrolTravel`, `GhostPatrol`, `GhostGoToCorner`, `GhostChase`

## 5. The algorithms run as models

`tools/cpu6502.py` is a 6502 interpreter (151 official opcodes, NMOS decimal mode, no hardware); it is itself checked by the first line below: **the ROM's own `Start` expands the maze, the nibble tables and both charsets to exactly the images of the independent decoders** (which were verified against the emulator's RAM, `12`). `tools/algorithm_models.py` then runs five more routines against models, and `tools/algorithm_models2.py` (OV-58) seven more, comparing the whole memory after every call (see the end of this section) written from the rules of section 4:

**OV-58: the other algorithms.**  Sets 2 to 7 (`tools/algorithm_models2.py` .. `algorithm_models7.py`) compare **the whole memory** (the zero page, `$0200-$9FFF` and the POKEY / GTIA / ANTIC page) byte for byte after every call, not only the results; the stack page is left out (below S it holds dead return addresses). ## 6. What the port does with this

- The named constants of section 2 become the `#define` / `enum` block of the C code (`src/c`, stage 74); the census of section 3 is the checklist that no number of the original is lost or invented (the C re-implementation of stage 76-78 can be compared routine by routine).
- Each algorithm of section 4 is one C function or a small group (`AddToScore` -> `add_to_score`, `SteerToTarget` -> `steer_to_target`, ...); the models of section 5 (all 22 algorithms, the whole frame included) are **ready-made unit-test oracles**: the same inputs, run against the C function, must give the model's outputs, and the model has been shown equal to the ROM.
- `RANDOM`: three call sites, each a pure function of one POKEY byte; the port takes the byte from a function `pokey_random()` so that the tests can replay the emulator's values and the game can use a real polynomial counter.
- `cpu6502.py` can run any other pure routine of the ROM on demand (for example the contact test or `StepAndDrawEntity` with a stubbed hardware), which is the quickest way to answer a question about the original while the C code is written.
