# 47 - Resources (stages 69-70) and the font

GENERATED by `python -I tools/asset_pack.py --write`, `python -I tools/check_assets.py --write analysis/evidence-assets-summary.txt` and `python -I tools/analyze_assets.py --doc docs/47-resources.md` from the ROM (`original/Pac-Man.rom`, not committed), `tools/asset_pack.py`, the checks of `tools/check_assets.py` and the curated text of `tools/analyze_assets.py`; tests: `tests/test_assets.py`. The data formats of the ROM were read in `12` (stage C11); this chapter **defines the asset format of the port** and shows that the pack is complete and equals what the original builds. The OS font the text needs is the one third-party part (`third-party/README.md`).

## 1. The result

- **Every byte of the ROM that is not code is in the pack**: 79 regions, 2246 bytes (the 76 labelled data regions of `tools/labels.py`, the two display lists and the cartridge header); with the 2925 traced instructions' bytes they cover all 8,192 bytes of the cartridge exactly once, no gap and no overlap (check 1).
- **One defined format, schema 2** (section 3): `resources/pack/assets.json` with nine decoded views (`charsets`, `maze`, `sprites`, `text`, `tunes`, `colours`, `tables`, `display_lists`, `font`) over the raw `regions`, a manifest with a hash of each file, four preview PNGs, and a reference loader (`asset_pack.load`, `asset_pack.ram_image`). The loader refuses another schema.
- **The pack equals what the original builds**: the loader's image of the game character set (808 bytes), the title set (192), the maze (920) and the tables (472) is **byte-equal to the RAM that `Start`'s own expansion code builds on the concrete 6502** (check 4). The maze legend is checked against the code: **256 dots + 4 power pellets = 260**, which is where the code ends a board; the four pellet cells are the four pellet squares of the code; the junction lists follow the cell formula (checks 5-7).
- **19 of 19 checks pass** (section 5). The pack is deterministic: written twice, the six files have identical hashes.
- **The pack is derived from the copyrighted ROM and is never committed**: it is written to `resources/pack/` (git-ignored, like the earlier `resources/decoded`); the repository holds the tool, the format and the tests. A port builds its pack from the owner's own ROM (section 2).
- **The OS font is in the pack** (schema 2, key `font`, section 4): the title and menu text has no glyphs in the cartridge (ANTIC mode 6 and the status row use the OS ROM font, `CHBASE = $E0`), so the pack carries the 64 glyphs the game's text uses, rendered from the **openly licensed font `EightBit Atari-Regular`** (Steve Boswell, SIL Open Font License 1.1; credit, licence and source in `third-party/README.md` and `third-party/EightBit-Atari-Fonts/OFL.txt`). The rendering is grid-exact and **bit-for-bit equal to the OS ROM's glyphs** (checks 14-17) - which is what makes it the right font, and raises a provenance question, which the owner has decided to accept (section 6).

## 2. What the pack is, and what it is not

The pack is a **view of the cartridge's data in a stable, documented format**, not a new game asset set: every number in it is a number of the ROM (the `regions` hold the raw bytes with their addresses), and the decoded views are the same bytes expanded the way `Start` expands them. It therefore carries the same copyright as the ROM; the owner decides what a released port ships (a tool that builds the pack on the player's machine from their own ROM, or redrawn assets in the same format). The format does not depend on the choice: a redrawn pack is a pack with the same keys.

What is **not** in it, and why: the **sound** (the dot, bonus, frightened, eyes, siren, ghost-eaten and death sounds are computed by code, not stored; `tools/core_sound.py` writes their sound-chip registers in the ROM's order, `44`; only the start tune and two pitch sweeps are tables); the **code** (`23`, `44`); and the **level and lattice constants** beyond the tables below, which are in the port-form core (`tools/core_tables.py`, `44`) and in `regions` as raw bytes.

## 3. The format, schema 2

`resources/pack/` holds `assets.json`, `manifest.json` (schema, ROM sha256, the sha256 of every other file), `charset_game.png`, `maze.png`, `sprites.png`, `text.png` (previews: **not colour-accurate**, the exact colours are in `assets.json`). Encodings: a byte string is a lower-case hex string; `rows` of a charset are 8-byte hex strings, one a glyph; a picture's `rows` are a list of integers, one byte a scan line; addresses are hex strings without `$`.

| Key | Content | Encoding |
|---|---|---|
| `schema`, `rom` | 1; the ROM's `sha256`, `size` 8192, `base` `A000` | ints and strings |
| `regions[]` | `name`, `kind`, `addr`, `size`, `bytes` (hex), `note`: all 2,246 non-code bytes | one entry per region |
| `charsets.game` | `ram` `3000`, `glyphs` 101, `rows` (8 bytes a glyph), `format` | ANTIC mode 4: 4 pixels of 2 bits a row (00 background, 01 COLPF0, 10 COLPF1, 11 COLPF2; COLPF3 when bit 7 of the screen code is set) |
| `charsets.title` | `ram` `1808`, `first_code` 1, `glyphs` 24, `rows` | the PAC-MAN logo set (CHBASE `$18`); glyph 0 is not in the ROM |
| `maze` | `rows` 23, `cols` 40, `codes[23][40]`, `legend`, `dots` 256, `power_pellets` (cells), `cell_to_coordinates` | screen codes of the game set |
| `sprites.shapes{}` | per shape: `addr`, `rows` (ints) | one byte a scan line, bit 7 leftmost |
| `sprites.pac_shape_pointers`, `ghost_score_pointers` | the code's pointer tables | ROM addresses |
| `text.strings{}` | `addr`, `mode` (2 or 6), `codes`, `ascii`, `colour_bits` | screen codes; code + `$20` = ASCII |
| `tunes` | `start_tune` (`audf1`, `audf2`, `step_jiffies` 4), `audf_sweep_down`, `audf_sweep_up`, `other_sounds` (a note) | AUDF values |
| `colours` | `game` (8), `game_names`, `title` (4), `dli` (4) | Atari colour bytes (hue high nibble, luminance low) |
| `tables` | `ram_0600` (the 472 nibbles), `slices`, the nine nibble tables by name (`JunctionExits` ... `ReverseDir`) and 17 ROM tables (`JunctionYList` ... `DliChbaseTable`) | lists of ints |
| `font` | `codes` 64, `first_ascii` 32, `rows` (8 bytes a glyph), `ram` `E000`, `format`, `source` (file, sha256, URL, commit, author, licence, credit) | 8 x 8, bit 7 leftmost; screen code c is glyph c, ASCII c + `$20`; `ram_image` puts it at `$E000` |
| `display_lists` | `DisplayList1` (game), `DisplayList2` (title): decoded entries (`mode` / `blank` / `jvb`, `lines`, `lms`, `dli`) | lists of objects |

A change to any key's meaning or encoding raises `schema`; the loader accepts only the schema it knows. Schema 2 added `font` and the `text.png` preview to schema 1; building the `font` key needs Pillow (the rest of `asset_pack.py` is standard library).

## 4. What is in it

**Regions by kind**: bytes 40 (797 bytes), display list 2 (69 bytes), header 1 (6 bytes), shape 21 (222 bytes), stream 3 (997 bytes), text 1 (10 bytes), text6 7 (99 bytes), words 4 (46 bytes).

**Character sets.** The game set is 101 glyphs (808 bytes) at `$3000`; codes 0-100. The title set is 24 glyphs (192 bytes) at `$1808`, codes 1-24. The maze, the status icons, the bonus items and the level indicator are all drawn with the game set.

**The maze** is 23 rows of 40 screen codes in ANTIC mode 4. Code 0 is blank, **1 is a dot** (256 of them), **2 a power pellet** (4, at cells (3,3), (3,36), (16,3), (16,36)), every other code a wall or decoration glyph (the lives row, the level indicator, the bonus item and READY! are drawn by code into the same area, `42`). A cell is 4 colour clocks and 8 scan lines; for an entity on a junction row / column `y = 8 * row + 36` and `x = 4 * col + 46`. The picture `maze.png` is this maze drawn with the game set (check it against `analysis/evidence-item-shots-summary.txt`, OV-32: the cells of real captures match the glyph pixels).

**The font.** The mode 6 lines and the status row are drawn with the OS font (`CHBASE = $E0`, `DliChbaseTable`); the cartridge contains only the logo and game sets. The pack's `font` holds the 64 glyphs for screen codes `$00-$3F` (the low six bits of a mode 2 / 6 code; ASCII `$20-$5F`: space, punctuation, digits, upper case), one byte a row, rendered from `third-party/EightBit-Atari-Fonts/EightBit Atari-Regular.ttf` by `asset_pack.render_font` (one pixel per design unit; the glyph box starts two rows below Pillow's em top). `text.png` shows the game's eight texts drawn with it, each glyph doubled in width as mode 6 does. **Credit**: font outlines (c) 2018 Steve Boswell, SIL Open Font License 1.1, from https://github.com/a8bit/EightBit-Atari-Fonts (commit `8b5a19f`); the upstream README, which carries the further credits, is kept unmodified next to the font.

**Tune and sweeps.** The start tune is two 64-entry AUDF tables stored to `AUDF1` / `AUDF2` one entry per 4 jiffies (channel 1 pure tone volume 8, channel 2 volume 4; the rendering is `analysis/start-tune.wav`, `22`); the two pitch sweeps are 0-terminated AUDF lists. **Colours**: `ColorsGame` (4 ghost colours, then the four playfield colours), `ColorsTitle`, `ColorsDli` (the band colours the display-list interrupts write, `35`). **Tables**: the nine nibble tables (`JunctionExits` ... `ReverseDir`) and the level, lattice, route, bonus and delay tables, by name. **Display lists**: the game screen is 23 mode-4 rows at `$0C00` under two mode-2 status rows at `$2000`; the title screen is mode 6 and 7 rows (`42`).

## 6. Limits

- **The pack is a decoding, not a re-creation**: that the decoded pictures *look right on the screen* is shown by earlier stages on real captures (ghost and Pac-Man pictures `16`, `20`; maze cells, items and pop-up `OV-32`; the title text `OV-53`), not by a new capture here; `maze.png` was looked at, the pixel comparison is the one of `OV-32`.
- **The previews are not colour-accurate** (four fixed colours); the exact colours are `colours` and the display-list interrupt schedule (`35`).
- **Provenance of the font (decided by the owner on 2026-11-18: accepted as it is, `49`).** The 64 glyphs are bit-for-bit those of the Atari OS ROM's character set (check 16, run against the local OS-B ROM, which stays in `original/`). The OFL licenses the font software of its author; it does not and cannot license anything Atari owns in the shapes, and the upstream README says only that no other copyright is expressed or implied. The font was chosen as the openly licensed 8 x 8 Atari font that matches the original; the plainly CC0 alternative (`damianvila/font-atascii`) has different shapes. Whether the OS font's pixel shapes need clearing for a release is not examined here (no legal advice); the owner chose to keep the font, its licence and its credit as they are, knowing this; the font file, its licence and its credit are in the repository, the rendered bitmaps only in the git-ignored pack.
- **The font covers the 64 codes the game's text uses**: the 128 internal codes of the OS set (the graphics and the lower case) are not in the pack because no text of the game uses them.
- **PAL**: the cartridge data is the same on PAL; the colour values of the original are NTSC hues (how a PAL display shows them was not checked here).
- **OV-68** (the collision registers) was closed after this stage (`50`): the overlap model is built and equals the GTIA's; what it takes is the scene the drawing leaves in the pages, which is in port form (OV-69, `44`); the sprite shapes of the pack are the pictures the drawing copies.
