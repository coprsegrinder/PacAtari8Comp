# 66 - Long-term preservation and archival (checklist stage 100)

Checklist stage 100: "Preserve the original software, analysis materials, reconstructed source code, resources, dependencies, documentation, and reproducible build instructions." `tools/make_archive.py` makes one folder, `build/archive/`, of five big files and three small ones, each with its SHA-256. It is made on the local disk only: copying it to storage, and any publication (GitHub), are the owner's steps.

## 1. What is kept, and where

| Part | Holds | Notes |
|---|---|---|
| `pacman-a8-history.bundle` | the whole Git history (`git bundle --all`): reconstructed source (`src/c`, `src/asm`), tools, tests, documentation, evidence summaries, the font and its licence, `LICENSE`, `NOTICE` | restores with `git clone`; no ROM inside |
| `pacman-a8-port-<v>-src.zip` | the release archive of stage 99 (`docs/65`) | made fresh from the committed tree |
| `pacman-a8-owner-materials.zip` | **the original software**: `original/` (the cartridge ROM, the two OS ROMs, the methodology list, the saved forum page) and `a800.zip` | **copyrighted and private**: for the owner only; never in the release or in Git |
| `pacman-a8-dependencies.zip` | the downloads the project was measured and built with (`external-tools/downloads`: Altirra 4.40, the cc65 snapshot) | the unpacked tools are rebuilt from them |
| `pacman-a8-local-evidence.zip` | the evidence Git ignores and that is small: emulator pictures, recordings, logs, session files, test aids (ignored files below `analysis/` and `tools/`) | |
| `ARCHIVE-MANIFEST.json`, `SHA256SUMS`, `README-ARCHIVE.txt` | the commit, every part's size and hash, the hashes of the three original ROMs, the restore steps | |

**Resources** (`resources/`, derived from the ROM) are not kept: they are rebuilt from the ROM by the documented tools (`docs/47`, `docs/63`). **Reproducible build instructions** are `docs/63` (the build), `docs/65` (the release) and `docs/64` (the verification), all in the history.

**Not kept**, with the reason: `build/` (rebuilt), `resources/` (derived), the extracted `external-tools/` (unpacked from the downloads), `analysis/raw-logs/` (about 8 GB of raw emulator logs, regenerated by the `tools/run_*.ps1` harnesses; the summaries that matter are in Git as `analysis/evidence-*-summary.txt`), and `Personal notes.txt` (the owner's; never archived, checked).

## 2. The commands

```
python -I tools/make_archive.py            # make build/archive/ (needs a clean Git tree: the archive records the commit)
python -I tools/make_archive.py --verify   # make it and verify it
```

## 3. What is verified

Every file against `SHA256SUMS`; the bundle verifies and clones; the clone's `HEAD` is the recorded commit and tracks the same files, equal to the working tree; **the release archive built from the clone alone is byte-identical to the one in the archive** (the project rebuilds from its history alone); every member of the three zips equals its source file; `Personal notes.txt` is in no part; the three original ROM hashes are recorded. The run is in `analysis/evidence-archive-summary.txt`.

## 4. Limits

- The archive is made at one commit. The commit that adds this chapter's evidence file comes after it and is not in the bundle (record it in the next archive).
- Everything stays on this machine until the owner copies it: a preservation copy on one disk is not yet preserved. Two copies on different media, and a re-check of `SHA256SUMS` from time to time, are the owner's part.
- Altirra and cc65 are in their downloaded form; their own licences apply (`NOTICE`, `third-party/`). The owner-materials part holds copyrighted ROMs: keep it private.
- Nothing was tested on real hardware (OV-01); the preserved evidence is of Altirra 4.40, NTSC, OS Rev B.
