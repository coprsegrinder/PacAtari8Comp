## 3. How the C port is built

- **CMake 3.16 or later**, C standard 99 with extensions off, and for clang and gcc `-Wall -Wextra -Wpedantic -Wconversion -Werror`. No option of its own: the compiler is chosen with `-DCMAKE_C_COMPILER`, the build type with `-DCMAKE_BUILD_TYPE` (Release and Debug are tested).
- **7 libraries** (`pm_app`, `pm_assets`, `pm_audio`, `pm_core`, `pm_platform`, `pm_render`, `pm_shell`), **14 executables** (`assets_check`, `audio_check`, `audio_selftest`, `constants_check`, `fs_sandbox`, `install_assets`, `pacman_a8`, `platform_check`, `render_check`, `shell_selftest`, `toolchain_check`, `vector_runner`, `vector_runner_swapped`, `world_check`) and **39 tests** under `ctest`. The program is `shell/pacman_a8`; the installer `assets/install_assets` makes the asset blob from the ROM.
- **No library but the C standard library** (`-lm` on Unix for the sound model); everything else is in `platform/` behind a small interface: files only through `fs.c` under the main folder, the clock through `timer.c`.
- **Configuration at run time**: none in files or the environment. The **main folder** is the current folder, or `--root DIR`; the ROM is `original/Pac-Man.rom` under it, the blob `resources/pack/assets.pmab`, the high score and options `save/`, the log `logs/`; nothing outside the main folder is ever read or written.

## 4. The recipes

All commands run from the project's root (the main folder).

### A. Build the C port and run its tests (the minimum)

```
# put your own ROM at original/Pac-Man.rom
cmake -S src/c -B build/c -G Ninja -DCMAKE_BUILD_TYPE=Release        # add -DCMAKE_C_COMPILER=clang (or gcc) to choose
cmake --build build/c
ctest --test-dir build/c --output-on-failure
```

`pacman_a8` and the tests under `build/c/`. The first `ctest` run makes `resources/pack/assets.pmab` from the ROM (the installer); the tests that need recorded vectors are **skipped, not passed**, until recipe C has been run.

### B. Build and test without CMake (any POSIX system with a C99 compiler)

```
sh tools/build_test_posix.sh gcc build/posix-gcc                       # extra flags after the folder: -O0, -fsanitize=address,undefined ...
```

the same sources, flags and tests as recipe A, in `build/posix-gcc/` (59 steps; used on Ubuntu in WSL2).

### C. Make the derived test data

```
python -I tools/make_vectors.py
python -I tools/make_app_sequences.py
```

the recorded calls and sessions in `resources/vectors/` (from the ROM; standard library only; about 17 and 2 minutes); then recipe A's `ctest` passes 37 of its 39 tests. **The other two (`vectors_gtia`, `vectors_gtia_world`) stay skipped**: their vectors are made by `tools/make_collide_vectors.py` from the emulator's collision logs (`analysis/raw-logs`, not reproducible without Altirra; the collision model is also checked on the live game by `50`).

### D. Play a game headless

```
python -I tools/make_rom_fuzz_replays.py build/replays 1 --frames 12000    # or tools/make_replay.py --script FILE OUT.pmrp
build/c/shell/pacman_a8 run build/replays/fuzz1.pmrp --video --audio --ppm last.ppm --time
```

the state hash, the run, video and audio digests, the time per frame, and the last picture. Options: `--frames N`, `--hashes FILE`, `--states FILE`, `--root DIR`, `--keep-high-score`, `--log`; `pacman_a8 info REPLAY`. The program writes only below the main folder.

### E. Regenerate the generated C sources

```
python -I tools/make_c_world.py; python -I tools/make_c_tables.py; python -I tools/make_c_assets.py
python -I tools/make_c_rom_layout.py; python -I tools/make_c_palette.py; python -I tools/make_c_constants.py
```

`src/c/core/world.[ch]`, `tables.[ch]`, `constants.h`, `src/c/assets/rom_layout.[ch]`, `src/c/render/palette.[ch]`; `tests/test_regression.py` runs all of them and checks that they write the same bytes.

### F. Check the whole project at once

```
python -I tools/run_regression.py                  # about 6 minutes: build, ctest, 30 golden games, the Python tests
python -I tools/run_regression.py --full           # adds clang, the C against the ROM on every game, the Linux build with sanitizers
python -I tools/check_clean_build.py                # the instructions of this chapter, on a clean copy of the project
```

a pass or a list of what differs; the golden digests are `analysis/golden-digests.txt`.

### G. Rebuild the ROM from the disassembly (the analysis side)

```
python -I tools/build_rom.py
```

assembles `src/asm/pacman.s` with ca65 / ld65 (`external-tools/cc65`) and compares size and SHA-256 with `original/Pac-Man.rom`: byte-identical or the first differing offset.

### H. The Python tests

```
python -m unittest discover -s tests -p "test_*.py"      # all; or name modules: python -m unittest tests.test_shell tests.test_behaviour
```

every test module (103 of them); the long ones (the comparisons with the ROM) take minutes.

## 5. The Python side

**198 tools** in `tools/` and **103 test modules** in `tests/`, all Python 3 with the standard library, **except**:

| Module | Files that import it | Used for |
|---|---|---|
| `PIL` | 10 (`asset_pack.py`, `check_assets.py`, `check_ghost_screenshots.py`, `check_item_shots.py`, ...) | the font, PNG previews, screenshot comparison |
| `numpy` | 25 (`analyze_full_waveform.py`, `analyze_ghost_sweep.py`, `analyze_tail_sound.py`, `analyze_tune_wav.py`, ...) | spectra and correlations of the sound recordings |

**Neither module is needed to build or run the port, to make the recorded vectors (recipe C) or the replays (recipe D), to compare the C with the ROM (`check_c_vs_rom.py`, `check_behaviour.py`) or to rebuild the ROM.** The scripts of the recipes that import Pillow, directly or through `asset_pack.py`, are: `make_c_assets`, `make_c_rom_layout`, `analyze_binary_docs`, `analyze_data_docs`, `analyze_resources_docs`. So recipe E (two of the six generators), the documentation generators and the Python tests of `run_regression.py` that use them need Pillow; no recipe script imports numpy; other third-party modules reached: test_app_frame.

## 6. The generators

The C sources `core/world.[ch]`, `tables.[ch]`, `constants.h`, `assets/rom_layout.[ch]` and `render/palette.[ch]` are written by `tools/make_c_assets.py`, `tools/make_c_constants.py`, `tools/make_c_palette.py`, `tools/make_c_rom_layout.py`, `tools/make_c_tables.py`, `tools/make_c_world.py` (every one starts with `GENERATED by`; do not edit them by hand): they need the ROM and Python only.

## 7. The evidence side

24 PowerShell scripts (`tools/*.ps1`) and 98 Altirra debugger scripts (`tools/*.cmd`) run the real game in Altirra 4.40 unattended and record traces, audio and screenshots into `analysis/` (`04` has the settings, the quirks of the debugger, and the fast-run copy of the settings). They need Windows, PowerShell, `external-tools/Altirra`, the NTSC OS ROM and your game ROM; none of the tests needs them, and their results are in `analysis/` and the register.

## 8. Checked on a clean copy

`python -I tools/check_clean_build.py` copies every file Git would keep (no `build/`, no `resources/`, no `original/`) into `build/clean-check/tree`, adds only your cartridge ROM, and then does recipes A, C, A again and D: **the build has no warnings; `ctest` with no derived data passes its tests and skips the ones that need the vectors; the vectors are made from the ROM; `ctest` then runs and passes all 39 tests; a replay is made and played, and its state, run, video and audio digests equal those of the golden game** (`analysis/evidence-clean-build-summary.txt`). The copy has no file that is not in the project.

## 9. Limits

The instructions are for Windows (WinLibs) and Ubuntu (WSL2); other systems are untried (OV-72). The Python side is Python 3.14 only. The derived data (`resources/`) is rebuilt, never shipped; a release would ship source and instructions, not the ROM or anything derived from it (stage 99).
