## 1. What a local variable is on this machine

The 6502 has no frames and no locals. A routine keeps what it needs in **registers** (A, X, Y; their roles are in `23`, stage 43), in **zero-page bytes** used as scratch, and, rarely, on the **hardware stack** (`PHA` / `PHP` / `TXS`, see section 5). Zero-page scratch is shared: the same byte is a temporary in one routine and a stored value in another. For the C port the question is therefore not 'which names are local' but **which bytes carry a value only inside one call** (an automatic variable) and which **carry it from one call to the next** (a `static` or a field of the game-state structure).

Per routine f, from the data flow of the code (details in `tools/analyze_locals.py`):

- **in**: f reads the byte before writing it on some path (its value comes from before the call: a parameter or kept state);
- **out**: f writes it and a caller still reads it after the call (a result or kept state);
- **TEMPORARY**: f writes it, it is not *in* and not *out*: born and dead inside one call, an automatic variable of f. **ARGUMENT** is a temporary that a routine called by f reads (the zero page used to pass a value, like `SrcPtr`).

The entry points, the interrupt handlers and a routine that nobody calls with `JSR` are treated as if every byte that some routine reads before writing it is read after them; `Start` never returns. The bytes the interrupt handlers read are also never temporaries of the main program, because an interrupt can come at any instruction.

A routine that writes a byte which neither it nor a routine it calls reads, and which no caller reads before rewriting it, is an initialisation or a store whose value is not used there. ## 6. What the port does with this

- **TEMPORARY** (sections 2 and 3): an automatic variable declared in the C function that corresponds to the routine; the zero-page byte is not needed.
- **ARGUMENT**: a parameter of the C function, or a local that is passed down; the zero page was only the transport.
- **STATIC**: a field of the game-state structure (or a `static`), initialised to the value the zero page has at power-on and reset by the same code that resets it on the 6502.
- **Everything else** (the GLOBAL variables of `25`) stays a field of the game state; the byte-exact equivalence tests of stages 86-87 compare those.
- Interrupt handlers (`VbiHandler`, `DliHandler1`, `DliHandler2`) share no temporaries with the main program in this analysis; where a shared scratch byte is used in both, section 3 lists the routines separately and the port must keep them apart.
