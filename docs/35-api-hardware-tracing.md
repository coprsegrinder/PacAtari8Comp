# 35 - API and Hardware Tracing (stage 59)

GENERATED by `python -I tools/analyze_hw.py analysis/raw-logs/hw-*.txt --doc docs/35-api-hardware-tracing.md` from the logs of `tools/run_hw_audit.ps1` (8 sessions of the real game in Altirra 4.40) and the static sites of `tools/analyze_io.py`. ## 1. The result

- **The OS API of the game is two calls.** `JSR SETVBV` at `$A460` (A = 7 = the deferred vertical-blank vector, X/Y = `$A5` / `$FD`) and `JMP XITVBV` at `$A60D`; all 8 SETVBV calls of the sessions had A=$07 X=$A5 Y=$FD and left `VVBLKD` = `$A5FD` (the immediate vector `VVBLKI` stays the OS's `$E7AE`). Everything else the game gets from the OS is the **shadow area** (section 3), and what it hands over are the vector `VDSLST` and the shadows.
- **Entered once per frame, without gaps:** the deferred vertical-blank handler `$A5FD` ran 116495 times in the sessions, every frame number and every OS clock value (`RTCLOK2`) following the previous one (frame gaps 0, clock gaps 0); the display-list interrupts ran 518677 (DLI1, the game screen) and 63775 (DLI2, the title screen) times.
- **The chips are what the shadows say** (section 3): at the entry of the handler the debugger's dump of ANTIC, GTIA and POKEY was compared with the OS shadows the game wrote the frame before (`DMACTL`, `DLIST`, `CHBASE`, `CHACTL`, `PRIOR`, the nine colour registers with the attract-mode transform, `IRQEN`): **1744905 checks, 0 violations**.
- **Nothing but the traced writes reaches the chips** (section 4): the same dump equals the last value the CPU wrote to the register, for the 36 registers the dump shows (`DMACTL`, `DLIST`, `PMBASE`, `CHBASE`, `NMIEN`, `PRIOR`, `GRACTL`, the positions, the colours, `AUDF1-4`, `AUDC1-4`, `AUDCTL`, `SKCTL`, `IRQEN`): **4187772 checks, 0 violations**. The 4663829 CPU writes to the chips were made by the game (`$A000-$BFFF`), by the display-list interrupt handlers (`$A573-$A5FC`) or by the OS (`$C000` up); none by any other code.
- **Every game write is a static site**: the game and its interrupt handlers wrote the chips at **71 of the 71** instructions of `analyze_io.py` that can write a chip register, and at no instruction that is not one of them.

## 6. Limits

- The chips are Altirra's model; the dump is the debugger's own (`.antic`, `.gtia`, `.pokey`). The trace shows the register file and the times of the writes, not the picture or the sound waves (those are in `docs/22-sound.md` and the colour work of `docs/16` and `docs/20`).
- The dump is taken at the entry of the frame handler only; the state between two interrupts is known from the write log (every write with its line), not from dumps.
- The sessions play with the test aids of their harnesses (`docs/04`); every claim above is about the game's own writes.
- The scan line is Altirra's `vpos` when the write is traced; the DLI lines are the lines at which the handler was entered.
